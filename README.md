# NOAA-Wetter

Leaflet-based weather dashboard with radar, wind particles, cloud shading, and German warning feeds (DWD + BBK/NINA). Frontend runs via Vite and can be served statically through nginx; backend helpers fetch and convert weather grids into static JSON under `public/data/`.

## Quickstart (development)
1. Install Node.js (>=18).
2. Install dependencies:
   ```bash
   npm install
   ```
3. Start dev server:
   ```bash
   npm run dev -- --host
   ```
   The map lives at http://localhost:5173.

## Building
```bash
npm run build
```
Bundles land in `dist/`. The `public/` folder (including generated `public/data/*`) is already served statically and copied through Vite.

## Data fetchers
Two Python helpers generate static JSON for wind and cloud cover. Use a virtualenv and install dependencies:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install herbie-data xarray cfgrib pandas requests numpy
```

Manual runs:
```bash
python3 scripts/noaa_wind_fetcher.py --out public/data/wind-global.json
python3 scripts/openmeteo_cloud_fetcher.py --out public/data/clouds.json
```

- `scripts/noaa_wind_fetcher.py` downloads the latest NOAA GFS 1.0° GRIB (10 m wind), validates the GRIB content-type, converts to Leaflet-Velocity JSON, and keeps scanMode 0 ordering. Intended cadence: every 6 hours.
- `scripts/openmeteo_cloud_fetcher.py` samples Open-Meteo GFS cloud cover into a coarse global grid (default 2°). Adjust `--step` if you need fewer API calls; writes a simple raster-style JSON.

## Deployment (nginx + systemd)
- Use `deploy/nginx-site.conf` as the site template. Important bits:
  - `/data/` uses `try_files` with **no SPA fallback**, ensuring JSON is served directly.
  - `/nina/api31/` proxies to `warnung.bund.de` with buffering and UA header.
  - CSP allows RainViewer, DWD, Open-Meteo, and warning feeds.
- Systemd units live in `deploy/systemd/`:
  - `noaa-wind-fetch.service` + timer (6-hourly)
  - `openmeteo-cloud-fetch.service` + timer (hourly)

Install services (example paths):
```bash
sudo cp deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now noaa-wind-fetch.timer openmeteo-cloud-fetch.timer
```

Serve the site:
```bash
sudo mkdir -p /var/www/noaa-wetter
sudo rsync -av . /var/www/noaa-wetter/
# enable nginx site after adjusting root path in the config
```

## Notes
- The frontend expects `public/data/wind-global.json` and `public/data/clouds.json` to exist; placeholder samples are included but should be regenerated by the fetchers.
- Wind JSON follows the Leaflet-Velocity GRIB-like schema with global coverage; clouds are rendered from a generated canvas overlay with adjustable opacity.
